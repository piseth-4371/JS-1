# LITTLE — Project Manual

## 1. Purpose
Learning project: a **paper-trading** control center for the Nasdaq-100 (Exness symbol `USTEC`).
Owner is a beginner learning Python/full-stack. Explain choices simply; give Windows PowerShell commands.
Success = rules followed, zero risk violations, reproducible backtest, working kill switch. **Not P&L.**

## 2. Stack
- Backend: Python 3.14, FastAPI, Pydantic v2, SQLAlchemy 2, (Alembic later), pytest
- Database: SQLite in week 1 (`backend/data/app.db`), PostgreSQL later via `DATABASE_URL`
- Market data: Exness **MT5 demo** (Standard account) via the `MetaTrader5` Python package (Windows only, terminal must be running)
- Weekend book: BTCUSDT from **Binance public market data** (no account, no key). Paper only; never send orders to Binance.
- Frontend (Day 5): React + Vite + Tailwind + lightweight-charts

## 2a. ONE-IDEA UNFREEZE (owner decision 2026-11-21) — read this first
History: frozen earlier on 2026-11-21 after 21 experiments, 53 strategy evaluations, 0 passes. The same day the owner unfroze it **for ONE new strategy idea only**, plus a weekly health check.
- **The one idea:** must be genuinely different from everything in `docs/experiment_journal.md` (no FVG/sweep/ORB/VWAP/silver-bullet variants, no new filters on old strategies). The owner picks it. Pre-register it from `docs/preregistration_template.md` (year-by-year, nearby settings, pre-mortem) and commit the rules BEFORE any result. Run it ONCE. Exness cost gate applies. No tweaks after the result.
  - Pass → paper forward test for months; nothing in `scanner.QUALIFIED` without the owner's separate approval; the 2025+ data only with separate approval.
  - Fail or inconclusive → record it and re-freeze. No second idea without the owner saying so in words.
- **Weekly health check:** a scheduled task (Saturday) runs tests, a safety check and a plain-English summary of the week's paper reports. It never changes strategies, rules, risk limits or data, and never commits.
- **Still allowed:** bug fixes; upkeep (MT5, backups, Telegram); news calendar before 2028; the study plan (short plan: days 3, 4, 7, 8, 14, 15); the E13 report when its data completes.
- **Still not allowed:** weekly strategy changes or tweaks (curve fitting); new dashboard features; more than one new idea; hosting/VPS work.
- E21 (turn-of-month paper forward test) keeps running on its own; no verdict before 36 trades (about 2029).
- **Team (2026-11-21):** the main session is the leader; subagents in `.claude/agents/` are `builder` (writes code), `tester` (runs tests, read-only) and `reviewer` (checks for bugs and rule breaks, read-only). Flow: builder → tester → reviewer → leader reports to the owner. Small tasks the leader does alone. Only the leader commits or pushes, and only when the owner asks.

- Every new pre-registration starts from `docs/preregistration_template.md` (since 2026-11-19). It includes a required year-by-year check (`app/backtest/yearly.py`): years with >= 10 trades count; in each period most counting years must be positive, the total without the best year must stay > 0, and at least 2 years must count. Failing it alone = inconclusive, never a pass. Applies to tests registered from now on; earlier verdicts are not re-judged.
- The template also requires a nearby-settings check (`app/backtest/nearby.py`): each free setting gets one smaller and one larger neighbour, fixed in advance and run one at a time. In each period at least 2/3 of neighbours must average above 0, and the chosen setting may be at most 2x the median neighbour (no spike). A neighbour can never replace the chosen setting. Failing it alone = inconclusive. Applies to tests registered from now on.
- The template also requires a pre-mortem written before any result (2-3 most likely reasons the test will fail; the report says which happened). Idea from the finance-psychology skill (confirmation bias).

## 3a. Original strategy — "NY Trend-FVG v1" (tested 2026-11-14: fails, kept for reference)
Times America/New_York. Closed bars only.
- Bias 15m: close > EMA50 and EMA20 > EMA50 → long (mirror short); else WAIT.
- Entries 09:45–11:30 only; flat by 15:55.
- 5m FVG: c3.low > c1.high (bull), c2 body ≥ 1.0×ATR14, gap ≥ 0.15×ATR14, close on bias side of session VWAP.
- Entry limit at FVG midpoint, expires after 6 bars. SL = c1.low − 0.10×ATR; stop distance must be 0.5–2.0×ATR.
- TP fixed 2.0R. Avoid ±30 min of high-impact US news (implemented in `core/news.py` for CPI/NFP/FOMC/GDP/PCE; calendar `app/calendar/us_high_impact_events.csv`, valid to 2027-12-31 — 2027 added 2026-11-20 from the official BLS, Fed and BEA schedules; extend it the same way before 2028. Outside its coverage the engine takes no new trades), extreme ATR, stale/gappy data.

## 4. Risk restrictions (NEVER raise without explicit owner approval)
- Virtual balance: **$1,000 paper** (owner approved 2026-11-13, was $10). Virtual money only; risk % limits unchanged.
- Risk/trade 0.5% default, 1% hard ceiling in code. Daily loss −2%, weekly −5% → lock.
- Max 3 trades/day, 1 open position, stop after 2 consecutive losses that day.
- Mandatory stop-loss. No martingale, grid, averaging down, or leverage beyond equity/price cap.
- If broker minimum lot × stop distance > allowed risk → **REJECT** (at $10 this rejected every USTEC trade; at $1,000 most fit).
- Risk Manager is deterministic Python with absolute veto. No LLM in the trading loop.
- **Live trading does not exist in this codebase.** Do not add a live order path.

## 5. Architecture
One FastAPI process. Engine loop: MarketData → Strategy (pure) → RiskManager (pure, veto) → PaperBroker (internal simulator) → DB journal. Kill switch is a persisted backend flag checked before every action.
